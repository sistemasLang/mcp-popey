=====================================================================
 MCP POPEY - INSTALACION EN VPS (nginx + pm2, sin Docker)
=====================================================================

Probado sobre: Ubuntu 24.04, 1 vCPU, 1 GB RAM, con otro proyecto Node
corriendo en la misma VPS bajo pm2 y nginx.

Consumo del MCP en ejecucion: ~100 MB de RAM, CPU casi nula en reposo.

Principio de esta guia: TODO lo que se instala queda aislado y listado,
para no tocar el resto de la VPS y poder desinstalarlo por completo
(ver seccion 9).

Cada bloque de comandos indica DONDE se ejecuta:
  [VPS]  en la VPS que va a alojar el MCP
  [PC]   en la computadora local (solo Opcion B)
  [DB]   en el servidor PostgreSQL
  [DNS]  en el panel del proveedor de dominio
Antes de ejecutar, mirar el prompt de la terminal para confirmar en que
maquina se esta.


---------------------------------------------------------------------
 0. QUE MODIFICA ESTA INSTALACION
---------------------------------------------------------------------

En la VPS:
  /opt/mcp-popey/                         app, Node 22 propio, cache de
                                          npm, logs, datos, panel de
                                          administracion (panel/admin/) y
                                          (Opcion A) deploy key de GitHub
  /etc/nginx/sites-available/mcp-popey    sitio de nginx
  /etc/nginx/sites-enabled/mcp-popey      symlink al sitio
  /etc/letsencrypt/...                    certificado de mcp.<dominio>
  pm2: proceso "mcp-popey"

Fuera de la VPS:
  DNS: registro A de <DOMINIO> apuntando a la IP de la VPS
  Servidor de base de datos: rol mcp_popey_ro, regla en pg_hba.conf,
    regla de firewall para la IP de la VPS
  GitHub (solo Opcion A): deploy key en el repo sistemasLang/mcp-popey
  Auth0: tenant con 2 APIs, la app del panel y la app M2M del servidor
    (seccion 6)

NO se toca: el Node del sistema, ~/.ssh, ~/.npm, pm2 (solo se agrega un
proceso), los otros sitios de nginx ni los otros procesos de pm2.

Por que un Node propio: el MCP requiere Node >= 22. Si la VPS tiene una
version anterior para otro proyecto, actualizarla podria romperlo. Se
descarga Node 22 dentro de /opt/mcp-popey/runtime y pm2 lo usa solo
para este proceso.


---------------------------------------------------------------------
 1. REQUISITOS
---------------------------------------------------------------------

[VPS] Verificar:
  uname -m                 x86_64 (si dice aarch64, cambiar "linux-x64"
                           por "linux-arm64" en la seccion 2)
  pm2 -v                   pm2 instalado
  nginx -v                 nginx instalado
  certbot --version        certbot instalado
  git --version            git instalado (solo Opcion A)
  free -h                  ver seccion 3 para la RAM necesaria
  ss -ltnp | grep -w 3030  NO debe mostrar nada (puerto libre)

Ademas:
  - Un subdominio (ej: mcp.midominio.com) con acceso para crear el DNS.
  - Acceso de administrador al servidor PostgreSQL.
  - Opcion A: acceso de admin al repo en GitHub (para la deploy key).
  - Opcion B: una PC con Node >= 22, git y acceso al repo.

En toda la guia, reemplazar (sin los < >):
  <VPS_IP>       IP publica de la VPS
  <DOMINIO>      subdominio del MCP, ej: mcp.midominio.com
  <DB_HOST>      host del servidor PostgreSQL


---------------------------------------------------------------------
 2. NODE 22 AISLADO
---------------------------------------------------------------------

[VPS]
  mkdir -p /opt/mcp-popey/app /opt/mcp-popey/runtime /opt/mcp-popey/logs
  cd /tmp

  BASE=https://nodejs.org/dist/latest-v22.x
  curl -fsSL $BASE/SHASUMS256.txt -o node-shasums.txt
  NODE_TARBALL=$(awk '/linux-x64\.tar\.xz$/ {print $2}' node-shasums.txt)
  curl -fsSLO $BASE/$NODE_TARBALL
  grep " $NODE_TARBALL\$" node-shasums.txt | sha256sum -c -
      -> debe decir "OK"

  tar -xJf $NODE_TARBALL -C /opt/mcp-popey/runtime --strip-components=1
  rm -f $NODE_TARBALL node-shasums.txt

  /opt/mcp-popey/runtime/bin/node -v
      -> v22.x.x
  node -v
      -> el Node del sistema sigue igual

Helper para usar npm con el Node 22 propio y con la cache dentro de
/opt/mcp-popey (asi no se ensucia ~/.npm). Vale solo para la terminal
actual: si se abre otra sesion, volver a definirlo.

[VPS]
  mcpnpm() { PATH=/opt/mcp-popey/runtime/bin:$PATH npm_config_cache=/opt/mcp-popey/.npm-cache npm "$@"; }

No hacer "export PATH=..." global: pm2 tambien se ejecuta con node y
pasaria a usar el Node 22, mezclando versiones con el daemon existente.


---------------------------------------------------------------------
 3. INSTALAR LA APP (elegir UNA opcion)
---------------------------------------------------------------------

  Opcion A - Compilar en la VPS
    Mas simple: no necesita PC, se actualiza con git pull.
    Requiere margen de RAM: la compilacion (npm ci con devDependencies
    + TypeScript) puede pedir 500 MB - 1 GB durante unos minutos.
    Recomendada si la VPS tiene 2 GB de RAM o mas.

  Opcion B - Compilar en la PC
    La VPS solo recibe el resultado compilado; no hay pico de RAM.
    Recomendada en VPS chicas (1 GB) con otros proyectos corriendo.

- - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
 OPCION A - Compilar en la VPS
- - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -

A.1 Crear una deploy key (clave SSH de SOLO LECTURA para este repo).
    Se guarda dentro de /opt/mcp-popey, no en ~/.ssh.

[VPS]
  ssh-keygen -t ed25519 -N "" -C "mcp-popey-deploy" -f /opt/mcp-popey/deploy_key
  cat /opt/mcp-popey/deploy_key.pub

[GitHub] Repo sistemasLang/mcp-popey -> Settings -> Deploy keys ->
  Add deploy key -> pegar la clave publica.
  Titulo sugerido: "mcp-popey <nombre de la VPS>".
  NO marcar "Allow write access".

A.2 Registrar la huella de GitHub (dentro de /opt/mcp-popey):

[VPS]
  ssh-keyscan -t ed25519 github.com > /opt/mcp-popey/known_hosts
  ssh-keygen -lf /opt/mcp-popey/known_hosts
      -> comparar con la huella ED25519 publicada en:
         https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints

A.3 Clonar y compilar:

[VPS]
  SSH_CMD="ssh -i /opt/mcp-popey/deploy_key -o IdentitiesOnly=yes -o UserKnownHostsFile=/opt/mcp-popey/known_hosts"
  GIT_SSH_COMMAND="$SSH_CMD" git clone git@github.com:sistemasLang/mcp-popey.git /opt/mcp-popey/app
  cd /opt/mcp-popey/app
  git config core.sshCommand "$SSH_CMD"

  mcpnpm ci                     # incluye devDependencies para compilar
  mcpnpm run build
  mcpnpm prune --omit=dev       # quita las devDependencies al terminar

  mkdir -p data && chmod 700 data

  Continuar en la seccion 4.

- - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
 OPCION B - Compilar en la PC
- - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -

B.1 Compilar y empaquetar:

[PC]
  git clone git@github.com:sistemasLang/mcp-popey.git
  cd mcp-popey
  npm ci
  npm run build
  tar -czf mcp-popey.tar.gz dist config scripts deploy package.json package-lock.json .env.example
  scp mcp-popey.tar.gz root@<VPS_IP>:/tmp/

  Si SSH usa un puerto distinto de 22:  scp -P <PUERTO> mcp-popey.tar.gz ...

B.2 Instalar en la VPS:

[VPS]
  # --no-same-owner: sin esto, root conserva el uid de la PC en los archivos
  tar -xzf /tmp/mcp-popey.tar.gz --no-same-owner -C /opt/mcp-popey/app
  rm -f /tmp/mcp-popey.tar.gz
  cd /opt/mcp-popey/app
  mcpnpm ci --omit=dev          # solo dependencias de produccion

  Si npm sugiere "npm install -g npm@...": IGNORARLO. Actualizaria el
  npm del sistema, que usan otros proyectos.

  mkdir -p data && chmod 700 data


---------------------------------------------------------------------
 4. BASE DE DATOS
---------------------------------------------------------------------

4.1 Crear el rol de solo lectura, una vez por cada base (lang, powerbi).
    El script esta en el repo: scripts/create_readonly_role.sql

[DB]
  psql -U <owner> -d <base> -v ON_ERROR_STOP=1 \
    -v ro_password='<password>' -v owner_role='<owner>' \
    -f scripts/create_readonly_role.sql

4.2 Permitir la conexion SOLO desde la VPS, en pg_hba.conf:

[DB]
  hostssl  <base>  mcp_popey_ro  <VPS_IP>/32  scram-sha-256

  Luego recargar PostgreSQL:  SELECT pg_reload_conf();

4.3 Firewall del servidor de base: abrir el 5432 SOLO para <VPS_IP>.

4.4 Probar que el puerto responde:

[VPS]
  timeout 3 bash -c '</dev/tcp/<DB_HOST>/5432' && echo "DB alcanzable"


---------------------------------------------------------------------
 5. CONFIGURAR .env
---------------------------------------------------------------------

[VPS]
  cd /opt/mcp-popey/app
  cp .env.example .env
  chmod 600 .env
  nano .env

Valores obligatorios:

  MCP_HOST=127.0.0.1        nunca 0.0.0.0: solo nginx debe llegar al MCP
  MCP_PORT=3030
  DATABASE_KEYS=lang,powerbi

  DB_LANG_HOST=<DB_HOST>
  DB_LANG_PORT=5432
  DB_LANG_NAME=<base>
  DB_LANG_USER=mcp_popey_ro
  DB_LANG_PASSWORD=<password del paso 4.1>
  DB_LANG_SSL=true

  (idem para DB_POWERBI_*)

  CIRCUITS_FILE=config/circuits.yaml
  CIRCUIT_ACCESS_FILE=config/circuit-access.yaml
  USERS_FILE=data/users.yaml

  Auth0 (ver seccion 6 para obtener cada valor):
  AUTH0_DOMAIN=<tenant>.us.auth0.com          sin https://
  MCP_RESOURCE_URL=https://<DOMINIO>/mcp      identifier de la API "MCP"
  ADMIN_API_AUDIENCE=https://<DOMINIO>/admin-api
                                              identifier de la API "Admin"
                                              (distinto del anterior)
  AUTH0_MGMT_CLIENT_ID=<client id de la app M2M del servidor>
  AUTH0_MGMT_CLIENT_SECRET=<client secret de esa app>
  AUTH0_DB_CONNECTION=Username-Password-Authentication
  BOOTSTRAP_ADMIN_EMAILS=<email del primer admin>   (seccion 6.2)
  PASSWORD_LINK_TTL_SECONDS=86400             vida del link para elegir
                                              contrasena (300 a 604800)

Una variable vacia (VAR=) toma el valor por defecto. Las rutas
relativas se resuelven desde /opt/mcp-popey/app (no desde la carpeta
donde se ejecuta el comando).

Lo unico que si debe completarse es DB_<KEY>_HOST / _NAME / _USER /
_PASSWORD de cada base listada en DATABASE_KEYS y las variables
AUTH0_* / MCP_RESOURCE_URL / ADMIN_API_AUDIENCE: si falta alguna, el
MCP no arranca y pm2 logs dice cual (sin mostrar valores).

Revisar tambien config/circuit-access.yaml: define que circuitos ve
cada rol y si tiene query_sql habilitado.

.env y data/ estan en .gitignore: ni git pull (Opcion A) ni el tar
(Opcion B) los pisan.


---------------------------------------------------------------------
 6. AUTH0, PANEL Y USUARIOS
---------------------------------------------------------------------

La identidad (login) la maneja Auth0. El rol, el tenant, el flag de
admin y el estado habilitado viven SOLO en data/users.yaml y se
gestionan desde el panel. No se envian mails: no hace falta configurar
ningun proveedor de email en Auth0.

6.1 Configurar el tenant de Auth0 (una vez):

[Auth0]
  a) Applications > APIs > Create API "MCP Popey"
       Identifier: https://<DOMINIO>/mcp        (= MCP_RESOURCE_URL)
       Signing algorithm: RS256
       Settings: Token Expiration 900, Allow Offline Access ON
  b) Applications > APIs > Create API "MCP Popey Admin"
       Identifier: https://<DOMINIO>/admin-api  (= ADMIN_API_AUDIENCE)
       Settings: Token Expiration 900
  c) Settings > Advanced:
       Client ID Metadata Document Registration   ON
       Dynamic Client Registration                OFF
       Resource Parameter Compatibility Profile   ON
       (opcional) RP-Initiated Logout End Session Endpoint Discovery ON,
       para que "Cerrar sesion" del panel cierre tambien la sesion de
       Auth0
  d) Authentication > Database > Username-Password-Authentication:
       Disable Sign Ups ON (nadie se registra solo)
       Recuperacion de contrasena self-service OFF (opcion de conexion
       forgot_password_enabled de New Universal Login): sin proveedor de
       email no funciona; el camino es "Nuevo link" en el panel
       Password Policy: Good o superior
       Security > Attack Protection > Brute-force Protection ON
  e) Applications > Create Application "MCP Popey Panel",
     tipo Single Page Application:
       Allowed Callback URLs:  https://<DOMINIO>/admin/
       Allowed Logout URLs:    https://<DOMINIO>/admin/
       Allowed Web Origins:    https://<DOMINIO>
       Connections: solo Username-Password-Authentication
     Copiar el Client ID (va en config.json del panel, 6.3).
  f) Applications > Create Application "MCP Popey Server",
     tipo Machine to Machine, autorizada para "Auth0 Management API"
     SOLO con estos scopes:
       read:users create:users update:users create:user_tickets
       read:clients create:clients update:client_keys
       read:client_grants create:client_grants delete:client_grants
     Copiar Client ID y Client Secret a AUTH0_MGMT_CLIENT_ID y
     AUTH0_MGMT_CLIENT_SECRET del .env. Es el secreto de mas valor
     del sistema: no compartirlo y rotarlo si se filtra.
  g) Clientes MCP (CIMD): cuando un cliente se conecta por primera vez,
     registrar y aprobar la URL de su documento de metadata (ej. Codex:
     https://chatgpt.com/oauth/codex/client.json) y habilitarle la
     conexion Username-Password-Authentication.
  h) n8n: si su credential no envia el Resource URL, configurar en
     Settings > General > API Authorization Settings el Default
     Audience = https://<DOMINIO>/mcp.

6.2 Primer admin (sin mails ni links):

El servidor NO crea al primer admin en Auth0: solo vincula a una
persona que ya existe ahi, con su propia contrasena.

[Auth0]
  User Management > Users > Create User
    Email:      <email del primer admin>
    Password:   la elige esa misma persona
    Connection: Username-Password-Authentication
  (Disable Sign Ups no lo impide: solo bloquea el registro publico.)

[VPS] en el .env:
  BOOTSTRAP_ADMIN_EMAILS=<ese email>

Al arrancar sin ningun admin habilitado, el servidor busca ese email en
Auth0 y lo da de alta como admin (sin acceso al ERP por /mcp). Si el
email no existe en Auth0 o Auth0 no responde, el MCP NO arranca y pm2
logs dice por que. Cuando ya hay un admin, la variable se ignora: no
revive admins dados de baja.

Recomendacion: poner SOLO el propio email y dar de alta al resto de los
admins desde el panel. Asi nadie elige la contrasena de otro. Quien
tiene acceso al dashboard de Auth0 es, en la practica, superadmin.

6.3 Publicar el panel:

[VPS] (o en la PC y copiar el resultado)
  cd /opt/mcp-popey/app/frontend
  mcpnpm ci
  mcpnpm exec ng build
  mkdir -p /opt/mcp-popey/panel/admin
  cp -r dist/frontend/browser/. /opt/mcp-popey/panel/admin/
  cp public/config.example.json /opt/mcp-popey/panel/admin/config.json
  nano /opt/mcp-popey/panel/admin/config.json
      issuer:   https://<AUTH0_DOMAIN>/      (con la barra final)
      clientId: el Client ID del paso 6.1 e)
      audience: el valor de ADMIN_API_AUDIENCE

config.json no tiene secretos (el panel es un cliente publico con
PKCE). Esta fuera del build: un nuevo build no lo pisa si se copia
solo dist/frontend/browser/.

6.4 Dar de alta personas y procesos (desde https://<DOMINIO>/admin/):

  Invitar persona: email, rol y tenant (o "sin acceso al MCP"), y
  opcionalmente admin. El panel muestra UNA SOLA VEZ un link de Auth0
  para que la persona elija su contrasena. Mandarlo por un canal
  confiable (quien lo abre primero se queda con la cuenta). Vence a las
  PASSWORD_LINK_TTL_SECONDS (24 h por defecto).

  "Nuevo link": regenera el link. Es tambien el camino para
  "olvide mi contrasena" (sin proveedor de email, el link de Auth0
  de la pantalla de login no es confiable).

  Cuenta de servicio (n8n): nombre, rol y tenant. El panel muestra UNA
  SOLA VEZ el client id y el secreto. En n8n, credential
  "MCP OAuth2 API":
      Register Client Automatically: OFF
      Grant Type:        Client Credentials
      Access Token URL:  https://<AUTH0_DOMAIN>/oauth/token
      Client ID / Secret: los del panel
      Resource URL:      https://<DOMINIO>/mcp
  "Rotar secreto" emite uno nuevo e invalida el anterior.

  Editar: rol + tenant, admin y habilitado. Deshabilitar corta el
  acceso al instante, aunque la persona tenga tokens vigentes. Siempre
  tiene que quedar al menos un admin habilitado.

6.5 Migrar desde la version con tokens estaticos (CLI de usuarios):

  La CLI ya no existe y los tokens viejos dejan de funcionar. Con el
  data/users.yaml anterior el MCP NO arranca (formato v1), a proposito:

[VPS]
  mv /opt/mcp-popey/app/data/users.yaml /opt/mcp-popey/app/data/users.v1.yaml.bak

  Despues: 6.2 (primer admin), arrancar, y dar de alta de nuevo a las
  personas y a n8n desde el panel (6.4). En cada cliente, quitar el
  header "Authorization: Bearer ..." fijo (ver 8.5).
  Rollback: volver a la version anterior y restaurar el .bak.


---------------------------------------------------------------------
 7. LEVANTAR CON PM2
---------------------------------------------------------------------

7.1 Copiar el archivo de proceso (esta versionado en el repo):

[VPS]
  cp /opt/mcp-popey/app/deploy/pm2/ecosystem.config.cjs /opt/mcp-popey/ecosystem.config.cjs

  Se copia FUERA de app/ para que un git pull o el tar no lo pisen.
  Incluye kill_timeout 6000 (el MCP espera hasta 5 s a que terminen las
  consultas en curso al reiniciar) y corta los reintentos si el proceso
  muere apenas arranca (.env o YAML invalido): mirar pm2 logs.

  MCP_HOST y MCP_PORT del bloque env de pm2 GANAN sobre el .env.

7.2 Arrancar y guardar:

[VPS]
  pm2 start /opt/mcp-popey/ecosystem.config.cjs
  pm2 save
  pm2 ls
      -> mcp-popey "online"; los otros procesos siguen igual

7.3 Verificar que pm2 arranca al bootear (normalmente ya esta
    configurado por el otro proyecto):

[VPS]
  systemctl is-enabled pm2-root
      -> "enabled". Si no, ejecutar: pm2 startup  (y seguir lo que indica)

7.4 Probar localmente:

[VPS]
  curl -i http://127.0.0.1:3030/mcp
      -> HTTP/1.1 401 Unauthorized   (correcto: falta el token)
         WWW-Authenticate: Bearer resource_metadata="https://<DOMINIO>/..."

  pm2 logs mcp-popey --lines 20
      -> "mcp-popey listening on http://127.0.0.1:3030/mcp (... users,
          issuer: https://<AUTH0_DOMAIN>/ ...)"


---------------------------------------------------------------------
 8. NGINX + HTTPS
---------------------------------------------------------------------

8.1 Crear el registro DNS:

[DNS]
  A  <DOMINIO>  ->  <VPS_IP>

[VPS]
  getent hosts <DOMINIO>
      -> debe devolver <VPS_IP>

8.2 Crear el sitio desde la plantilla del repo, reemplazando <DOMINIO>
    (ej: mcp.midominio.com):

[VPS]
  sed 's/<DOMINIO>/mcp.midominio.com/' /opt/mcp-popey/app/deploy/nginx/mcp-popey.conf \
    > /etc/nginx/sites-available/mcp-popey
  grep server_name /etc/nginx/sites-available/mcp-popey
      -> debe mostrar el dominio real, sin < >

  ln -s /etc/nginx/sites-available/mcp-popey /etc/nginx/sites-enabled/mcp-popey
  nginx -t && systemctl reload nginx

8.3 Certificado HTTPS (certbot agrega el bloque SSL a ESTE sitio):

[VPS]
  certbot --nginx -d <DOMINIO>

8.4 Probar desde afuera:

[PC o cualquier maquina]
  curl -i https://<DOMINIO>/mcp
      -> HTTP/1.1 401 Unauthorized
  curl -s https://<DOMINIO>/.well-known/oauth-protected-resource/mcp
      -> {"resource":"https://<DOMINIO>/mcp","authorization_servers":[...]}
  curl -i https://<DOMINIO>/admin/
      -> HTTP/1.1 200 (el panel)
  curl -i https://<DOMINIO>/admin/api/users
      -> HTTP/1.1 401 Unauthorized

8.5 Conectar un cliente: SIN header fijo. Con un header Authorization
    fijo, el cliente no intenta OAuth. El cliente descubre Auth0 solo y
    abre el login en el navegador.

  Claude Code:
    claude mcp add --transport http popey https://<DOMINIO>/mcp
    y dentro de Claude Code: /mcp -> popey -> Authenticate
  Claude (web / Desktop): Settings > Connectors > Add custom connector,
    URL https://<DOMINIO>/mcp
  ChatGPT / Codex: agregar el servidor MCP con la misma URL.
  n8n: ver 6.4.

  Una persona sin rol/tenant o deshabilitada recibe 403 (Forbidden),
  no un nuevo login.

IMPORTANTE: nunca exponer el puerto 3030 en el firewall ni usar HTTP
sin TLS: el access token viaja en cada request.


---------------------------------------------------------------------
 9. DESINSTALAR POR COMPLETO
---------------------------------------------------------------------

[VPS]
  pm2 delete mcp-popey
  pm2 save

  rm -f /etc/nginx/sites-enabled/mcp-popey
  rm -f /etc/nginx/sites-available/mcp-popey
  nginx -t && systemctl reload nginx

  certbot delete --cert-name <DOMINIO>

  rm -rf /opt/mcp-popey

Verificar que no queda nada:

[VPS]
  pm2 ls                          -> sin mcp-popey
  ls /etc/nginx/sites-enabled/    -> sin mcp-popey
  certbot certificates            -> sin <DOMINIO>
  ls /opt                         -> sin mcp-popey
  ss -ltnp | grep -w 3030         -> sin salida

Fuera de la VPS:

  [GitHub] (solo Opcion A) Settings -> Deploy keys: borrar la clave
           de esta VPS.
  [DNS]    Borrar el registro A de <DOMINIO>.
  [DB]     Firewall: quitar la regla del 5432 para <VPS_IP>.
  [DB]     pg_hba.conf: quitar la linea de mcp_popey_ro y ejecutar
           SELECT pg_reload_conf();
  [DB]     (Opcional) borrar el rol. En CADA base donde se creo:
               DROP OWNED BY mcp_popey_ro;
           y luego una sola vez:
               DROP ROLE mcp_popey_ro;


---------------------------------------------------------------------
 10. ACTUALIZAR A UNA NUEVA VERSION
---------------------------------------------------------------------

Primero definir el helper mcpnpm (seccion 2) en la terminal.

Opcion A:

[VPS]
  cd /opt/mcp-popey/app
  git pull
  mcpnpm ci
  mcpnpm run build
  mcpnpm prune --omit=dev
  pm2 restart mcp-popey

  Si cambio el panel, repetir 6.3 sin pisar config.json
  (solo cp -r dist/frontend/browser/. ...).

  Si se edito config/circuit-access.yaml en la VPS, git pull avisa del
  conflicto en vez de pisarlo.

Opcion B:

[PC]
  git pull && npm ci && npm run build
  (cd frontend && npm ci && npx ng build)
  tar -czf mcp-popey.tar.gz dist config scripts deploy package.json package-lock.json .env.example \
    frontend/dist/frontend/browser frontend/public/config.example.json
  scp mcp-popey.tar.gz root@<VPS_IP>:/tmp/

[VPS]
  cd /opt/mcp-popey/app
  cp config/circuit-access.yaml /opt/mcp-popey/circuit-access.yaml.bak
  rm -rf dist
  tar -xzf /tmp/mcp-popey.tar.gz --no-same-owner -C /opt/mcp-popey/app
  rm -f /tmp/mcp-popey.tar.gz
  mcpnpm ci --omit=dev
  pm2 restart mcp-popey

  OJO: el tar incluye config/ y pisa circuit-access.yaml. Si se habia
  editado a mano en la VPS, restaurarlo desde el .bak.
